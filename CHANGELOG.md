# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) where releases are tagged.

## [Unreleased]

### Fixed

- The API image could not call OpenAI: `openai==1.52.2` passes `proxies` to httpx, which httpx 0.28 (installed unpinned) removed, so every model call failed with a TypeError. `httpx==0.27.2` is pinned in `api/requirements.txt`.
- A saved view link (`?zestawienie=`) no longer disappears after the first click: the browse view rewrote the page address with only its own parameters.
- Prompt injection: committee and person names reach the model as one line each with a valid SQL literal (the hint for Kukiz'15 was broken SQL); the previous turn and the question in the answer prompt are JSON strings, so a line break in them cannot add instructions or fake rows; both prompts treat that text as data. „Potem napisz…” no longer asks which POTEMPA was meant. Tests in `TestPromptInjection` and three `injection` items in the evaluation set.
- Bar charts with a few rows no longer collapse into one line under their title: every bar gets the same height, title and axes come on top.
- Questions with „między” (between elections, between parties) or „różnica” no longer ask which gmina was meant: the words matched the gminas Miedzna, Miedźna and Miedźno and the surname Różniak.
- False clarifications: 45 of the 306 evaluation questions ended in a clarification before the model was asked, now none. Round words no longer match the gmina Turek, „mieli” no longer Mielec; a closer or longer place name beats a look-alike (Szczecin/Szczecinek, Bielsko-Biała/Biała), a person named in full beats places like the given name or surname (Przemysław Czarnek: Przemyśl, Czarne); namesakes without a candidacy in the question's year are dropped; „w mieście X” picks the town gmina. Marek Borowski's candidacies 1991–2023 are one person (override). Declined town names are recognised: „Białegostoku”, „Białymstoku”, „Krasnymstawie”, „Jeleniej Górze”, „Białej Podlaskiej”; a surname matching any word of a place name („Dąbrowie Górniczej”, „Białej Podlaskiej”) no longer adds look-alike persons. A capitalized voivodeship („w województwie Podlaskie”) is no longer dropped for a look-alike surname (PODLASKA).

### Added

- Question length and session limits: `/ask` rejects questions over `QUESTION_MAX_CHARS` (500) with 400, and the UI fields stop at that length; each UI session (`X-Session-Id`) may ask `SESSION_QUESTION_LIMIT` (100) questions per UTC day, after which the UI suggests „Przeglądaj wyniki”.

- Anonymized logs before LLM analysis: the feedback triage (`scripts/triage_feedback.py`) and accepted thumbs-up examples (`add_sql_example.py --review`) replace e-mail addresses, links, IP addresses, account and card numbers, PESEL and phone numbers in user questions with placeholders (`api/services/anonymize.py`); election numbers (years, dates, TERYT, vote counts) stay.

- Another LLM provider through configuration: `LLM_PROVIDER=azure` sends every model call (SQL, answers, embeddings, speech) to Azure OpenAI at `AZURE_OPENAI_ENDPOINT` (e.g. an EU region; model settings are deployment names), and `OPENAI_BASE_URL` points the default provider at an OpenAI-compatible endpoint (`api/services/llm_client.py`).

- Emergency mode: an OpenAI error no longer ends in HTTP 500. The answer says the model is unavailable and offers the matching „Przeglądaj wyniki” view (election, year, round, turnout or results, level read from the question), opened with one click; for 60 s after the error no OpenAI call is made, so further questions get it at once (cached SQL still answers).

- Cost limit per question: `QUESTION_COST_LIMIT_USD` (default 0.05 USD). Model calls have output ceilings, and a call that could cross the limit is skipped (the repair, clarification queries, the answer text, which then falls back to the deterministic summary); the question log records `cost_usd`.

- Semantic SQL cache: a paraphrase of an earlier question („W której gminie frekwencja była najwyższa w 2023?”) reuses its validated SQL without a model call, when the embeddings are close (`SEMANTIC_CACHE_MIN_SIMILARITY`, default 0.92) and both questions name the same entities, numbers, elections and meaning words (highest/lowest, level, measure, round…) and share most content words; the SQL expander names the earlier question.

- Cost panel: every `/ask` adds its tokens per model to `token_usage` (UTC day × API key hash × model); `GET /costs` (admin keys, `ADMIN_API_KEYS`) returns them with a USD estimate (`LLM_PRICES_USD_PER_1M`), and the UI shows them at `?panel=koszty`: total cost, tokens per day by model, usage by key and model.

- Agents: `POST /mcp` is an MCP server with the tools `ask`, `schema` and `query`, and `POST /query` runs an agent's own SQL; both go through the same guards as the model's SQL (validation, cost limit, read-only role) and the `/ask` limits.

- Saved views: „🔗 Zapisz jako zestawienie” under an answer (also in chat mode) gives a link `?zestawienie=<id>` that shows the same query's table, chart, map and SQL on current data without asking the model again. The API stores only queries it generated itself (`saved_views`, `view_id` in `/ask`, `GET /views/{id}` through the SQL guard).

- „🎲 Pokaż coś ciekawego” under the question box shows a random ready-made report (a verified query run without the LLM: rows, chart, map, SQL), never the same one twice in a row.

- Chat mode: „Tryb czatu” shows the questions and answers as a conversation; every question follows up on the previous answer. ✏️ corrects an earlier question: it is asked again and the later turns are dropped. „Nowa rozmowa” starts over.

- Voice input: „🎤 Albo nagraj pytanie” records the question in the browser; `POST /transcribe` turns it into text (`OPENAI_TRANSCRIBE_MODEL`, default `gpt-4o-mini-transcribe`, a vocabulary hint with election terms and party names), which goes into the question field to be checked and sent like a typed question. Same per-client question limit; recordings up to `TRANSCRIBE_MAX_BYTES`.

- Empty results explained: when a query that ran finds no rows, the answer says why (`answer.empty_reasons`): an election-year not in the database, with the loaded years („W bazie nie ma wyborów: Sejm 2021. Wczytane lata: …”), otherwise the conditions no row met, read from the SQL; the UI shows them in the „Brak wyników” box.

- Text description of maps (accessibility, print): under every choropleth a line says what it shows for how many units, its three highest and lowest units with their values from the rows, and how many drawn units have no value (`map_units.map_description`); voivodeship names are written in lower case.

- PDF reports: `GET /pdf/units/{teryt}` (unit card: GUS statistics, turnout and the winner of every election) and `GET /pdf/elections/{election}/{year}` (election card and national results of every round), with bars, Polish formatting and the sources in the footer; „Przygotuj raport PDF” on the unit and election cards. Fixed SQL, no model; fpdf2 with DejaVu Sans (`fonts-dejavu-core` in the API image, `REPORT_FONT_DIR`).

- Answer style: `/ask` takes `style` (`journalistic`, default: plain language, rounded; `technical`: exact values, named measures and units), chosen in the UI next to the question; the number check is the same for both, and the technical style opens the SQL section.

- Suggested follow-up questions: answers from generated SQL carry up to three next questions (`answer.follow_ups`) built from the result and the loaded elections, without the model: the previous election of the same kind, a finer territorial level and the change against that election; a click in the UI asks one as a follow-up.

- Caveats chosen by the shape of the result, not only by data gaps: a result that reached the row cap (only part shown), percentages resting on fewer than 1,000 votes or voters (rankings of gminas and precincts now return their base), and Warsaw shown as separate districts in gmina rows.

- Chart choice, titles and captions: the SQL call also returns `chart` (type from bar, line, scatter or none, and a short Polish title); the UI uses the type only when the rows fit it, otherwise the deterministic rule (scatter, line, bar) decides, and drops a title with numbers the question does not name. Charts have Polish axis titles and the data source as subtitle, so exported images carry it; bars and maps of change rows show the change in points.
- Summary of large results: a result above 30 rows reaches the answer model as its first and last rows plus the rows with the highest and lowest main value (not only the first 30 rows), and the deterministic summary names the highest and lowest value with its unit (and year in a time series), all copied from the rows.

- Query explanation in Polish: every answer carries `answer.explanation`, lines read from the SQL itself with sqlglot (sources, conditions such as „rok (b) = 2023”, calculations such as korelacja or podział mandatów, grouping, order, row limit), shown above the SQL in the UI; it is derived from the query, not written by the model, so it cannot differ from what produced the rows.

- Hypothetical seats: besides another method (`v_seat_methods`) and another threshold, the model handles a joint list („gdyby KO, TD i Lewica startowały razem”: 265 seats in 2023 instead of 248) and one national constituency with `mart.allocate_seats` (rule, two curated examples, two evaluation items); every such answer notes it is a simulation with the same votes.

- Changes between any two elections by party family: besides `v_party_change` (previous election of the same kind), the model joins `v_party_results` to itself for other pairs (Sejm 2011 vs 2023, Sejm 2023 vs EP 2024) and returns `comparable`, so the PO → KO caveat applies; two curated examples and a `change` evaluation family.

- Correlations with GUS statistics: questions such as „czy bezrobocie w gminach wiązało się z poparciem PiS” get one row with `corr` (r), `regr_slope`, `regr_r2` and the number of gminas or powiats (a new SQL rule, a curated example, two evaluation items in a new `gus` family), and the answer notes that a correlation across units is not causation.

- Automatic ordering: the SQL guard adds an `ORDER BY` to a generated query without one (by `year` for trends, otherwise descending by the first measure such as votes, pct or seats, the other columns breaking ties), so the rows and the rows a `LIMIT` keeps no longer depend on the plan; the row cap (`MART_MAX_ROWS`) was already automatic.
- Too expensive queries are not run: a generated query whose planner cost (`EXPLAIN`, read-only) is above `MART_MAX_PLAN_COST` (default 5,000,000; the heaviest evaluation reference query costs about 360k) goes straight to the repair attempt with its plan instead of holding a connection until the statement timeout; `run_eval.py --check` applies the same limit to the reference queries.
- SQL repair with `EXPLAIN`: when the first query fails after planning (a timeout, a run-time error), the repair prompt gets its `EXPLAIN` plan (read-only, on the validated query, at most 30 lines) next to the error, plus a hint for timeouts (filter earlier, use the views and the matched keys); `meta.explain` records whether a plan was sent.
- Prompt caching: the SQL prompt now starts with its constant part (instructions, rules, loaded elections; about 8,400 characters) and puts the question-specific schema, entities and examples after it, so OpenAI's automatic prompt caching serves that prefix at the cached-input price; cached prompt tokens are in the telemetry (`cached_tokens`) and in a new `cached` column of the evaluation report, priced with `EVAL_USD_PER_1M_CACHED_INPUT`.
- Model routing: the cheap `OPENAI_CHAT_MODEL` (default `gpt-4o-mini`) writes the SQL first, and a failed query is repaired by the stronger `OPENAI_REPAIR_MODEL` (default `gpt-4o`); `models` in the telemetry names the model of each attempt, and the evaluation report records both.
- Query plan before SQL: the model fills a short plan (relations, filters, grouping, output columns) before the SQL in the same response, with no extra request; the plan of the query that ran is in the telemetry (`_dynamic_sql_meta.plan`) and above the SQL in the UI.
- Schema selection by embeddings: with an OpenAI key, the relation descriptions (schema comments) are embedded once per mart load and the eight relations closest to the question join the keyword choice; a question naming no election kind gets those plus the shared relations instead of the whole schema. `FAMILY_KEYWORDS` stays the safety net (its relations are always described, and it chooses alone without a key or when embeddings fail); `schema_selection` in the telemetry and the evaluation report says which way was used.
- Geographic questions: `mart.unit_attributes` gives today's gminas their cities with powiat rights (66), voivodeship capitals (18), „ściana wschodnia”, the Baltic coast (32 gminas) and the land border with each neighbouring country (`borders`: DE, CZ, SK, UA, BY, LT, RU), derived from the map boundaries by `scripts/derive_gmina_borders.py`. Questions about the coast, the border, capitals or cities with powiat rights get the table in the prompt; neighbouring countries („przy granicy z Litwą”) are no longer taken for surnames. Two curated examples and four evaluation questions (366 in total).
- Periods become loaded years: decades („lata 90.”, „latach dwutysięcznych”, „1990s”), ranges („2001-2011”, „między 2005 a 2015”), open ranges („od 2005”, „po 2015”, „przed 2005”, „do 2011”) and relative periods („w ostatniej dekadzie”, „trzy ostatnie wybory”, „ostatnie wybory”) are turned into `year BETWEEN` bounds and the loaded years of the elections the question is about, listed in the prompt. Six evaluation questions cover periods (362 in total).
- Refusal for questions outside the data: polls, exit polls, forecasts and future results („Kto wygra wybory w 2027?”, „Ile mandatów zdobędzie KO?”, „Who will win the next election?”) get a fixed Polish or English refusal before any SQL or model call (`api/services/scope.py`, intent `out_of_scope`), shown in the UI with the 👍/⚠️ buttons; past tense and the seat simulator's conditionals are still answered. `triage_feedback.py` reports a thumbs-down refusal as a rule to check. Eight evaluation items expect a refusal, and `run_eval.py --check` fails when an answerable item is refused (356 items in total).
- Definitions from the repository docs: „Co to jest próg wyborczy?”, „Jak działa metoda D'Hondta?”, „What are party families?” and other definition questions without a year are answered with the curated text of `docs/DEFINITIONS.md` (14 terms, Polish and English), with no SQL and no model call; the UI marks the answer as a definition from the project docs, links its sections and offers the 👍/⚠️ buttons; `triage_feedback.py` reports a thumbs-down definition as a fix to `docs/DEFINITIONS.md` instead of proposing a query. Ten evaluation items check the matched section, and `run_eval.py --check` fails when a data question is caught as a definition (348 items in total).
- Questions in English: English election words select the relations of their election (`FAMILY_KEYWORDS`) and keep mart-only elections away from the Sejm templates; `entity_aliases.csv` gains English committee names („Law and Justice”, „Civic Coalition”, „Third Way”, „Polish People's Party” …) and a new `place` kind for English place names („Warsaw”, „Cracow”, „Masovian”, „Lesser Poland” …); common English words are entity stopwords. The answer text follows the question's language (the number check is unchanged; caveats and clarifications stay Polish). A unit or committee matched under two names counts once, and committees of the question's years come first before the per-kind cut. Twelve evaluation questions are in English (338 in total).
- Typos and missing Polish letters: a long name word may carry one wrong or swapped letter („Platfromy”, „Gdańksu”); a person matched only through a near match yields to a place or person the word names more closely („Krakowa” is not KRASOWSKI, „Kosiniak-Kamysz” not KAMYSZEK); persons who ran in the question's year survive the per-kind cut („Nawrocky w 2025” is Karol Nawrocki), and the election the question names narrows namesakes of that year („Duda … prezydenckich 2015”). Eight evaluation questions cover typos and unaccented text (326 in total).
- Colloquial names: `api/services/mart/entity_aliases.csv` adds names such as „Platforma”, „Konfa”, „ludowcy”, „Koalicja Obywatelska”, „Olek Kwaśniewski”, „Bronek Komorowski”, „Korwin” and „Kosiniak” to `entity_lexicon` (an alias matching nothing fails the build); a person's colloquial name shares its `person_id` and is never a second clarification option. Committee aliases of five or more letters now match inflected forms („Konfederacji”, „Platformy”). Eight evaluation questions cover them (318 in total).
- Comparative follow-ups: „A jak to wypada w porównaniu z 2019?” after an answer keeps the previous filters and asks for both sides in one result (a column per side and the difference) instead of replacing the year; the follow-up toggle defaults to on for short comparisons. The evaluation set has four follow-up items (`previous` turn), 310 questions in total.
- Multi-part questions: when one question asks two or three separate things, the model may return one SELECT per part (`{"parts": [{"title", "sql"}]}`); each part passes the SQL guard (one unsafe part rejects the answer), runs read-only, and the combined rows carry their part title in `part`. The SQL panel shows the parts as `-- part:` blocks, and the UI draws one table, chart and map per part.
- Clarifications with ready queries: an ambiguous question gets at most four options, each with a short description and a validated query written in one model call; the UI shows the description under the button, and a picked option runs its cached query without another model call.
- Thumbs-down triage: `scripts/triage_feedback.py` groups the thumbs-down questions by likely problem with the LLM (`feedback_groups.md`) and proposes a corrected query per question through the usual SQL prompt and guard; proposals with rows wait in `example_proposals.jsonl` for `add_sql_example.py --review`.
- Evaluation of LLM-written SQL: `tests/eval/questions.jsonl` (306 questions across all election families, each with a reference query or an expected clarification) and `scripts/run_eval.py`, which grades the model's rows against the reference rows and reports accuracy, clarifications, repairs, tokens, cost and time per family. CI checks every reference query against the built mart (`--check`); the nightly `Eval` workflow restores the published mart and runs the evaluation with the real model when the `OPENAI_API_KEY` secret is set. Reports record the model and a hash of the SQL rules (prompt version); `--baseline` compares with the last successful nightly report and fails on more than `EVAL_MAX_REGRESSIONS` (default 5) questions that stopped passing, listing them.
- Local recall referendums 2015–2026 (`mart.local_referenda`, 186 referendums, 231 questions): `scripts/fetch_local_referenda.py` decodes PKW's term sites on wybory.gov.pl (protobuf, no schema) into `data/pkw_html/local_referenda.csv`; the derived build checks the votes and that the commission's validity (3/5 of the voters of the organ's election) and outcome statements follow from them. Questions about recalls (odwołanie) and local referendums get the table in the prompt.
- Gmina council elections 1994 (`rada`, 2468 councils, 51,926 seats): KBW's candidate file and gmina totals (`samo1994kand`, `samo1994gm`), with the pre-1999 gmina codes and old voivodeships, single-member districts in gminas up to 40,000 inhabitants and lists in larger cities; checked against the official gmina totals and the seat allocation (modified Sainte-Laguë, `allocate_seats` method `sainte_lague_modified_whole`). Candidates are linked to persons through the 1999 powiat of their gmina. KBW publishes no 1990 local election files.
- More GUS statistics (`v_gus_units`, 2002–2024): age structure (`age_preworking_pct`, `age_working_pct`, `age_postworking_pct`), gmina budget income per resident (`gmina_income_per_capita`) and census education (`higher_education_pct`: NSP 2021 by gmina, NSP 2011 by powiat; NSP 2002 is not in BDL by unit); `fetch_gus_bdl.py --indicators` fetches only new indicators; GUS keywords for education, seniors and gmina wealth.
- Senate by-elections 2003–2025 (`mart.senat_byelections`, 24 districts): `scripts/scrape_senat_byelections.py` reads PKW's result announcements (page text, RTF, PDF) into `data/pkw_html/senat_byelections.csv`; the derived build loads it and checks that candidate votes sum to the valid votes and the winner has the most votes. By-election candidates are linked to persons (`person_id`, `v_person_history` chamber `senat_uzup`) and shown on the person card.
- Precinct areas and „mój obwód”: `mart.precincts.boundary_description` keeps PKW's „Opis granic” (Sejm 2011, 2015, 2019, 2023); `GET /precincts/find?teryt_gmina=&street=` lists the precincts of the latest such year whose area names a street or village, and the „Wyniki obwodowe” panel shows them with the commission address and jumps to the precinct.
- Sejm and Senate district borders on browse maps (2001 onwards): `GET /districts` gives each district's gminas from the precinct register, `map_units.district_borders` draws the edges between districts from the shared gmina boundaries (no geometry library); Wrocław, Łódź and Kraków, split between two Senate districts, get no inner line.
- English UI labels: `?lang=en` (switch link in the header) translates panel titles, controls, buttons and election/level names (`streamlit_app/i18n.py`); answers, captions and data stay Polish; browse links keep the language.
- Candidate votes per gmina: plain view `mart.v_candidate_gmina_votes` (Sejm, Senate, EP; in the prompt with those elections), `GET /persons/{id}/gminas` and a „Głosy w gminach” map with top gminas on the person card.
- Image export and phone layout: charts and maps download as SVG and PNG on request (charts via vl-convert, maps drawn as SVG from the boundaries, `map_units.features_svg`); a compact layout below 640px.
- Dark mode and accessibility: the hero and custom styles follow the system dark theme (Streamlit's default „Use system setting”; maps switch to a dark basemap), visible keyboard focus, screen-reader descriptions of the answer/browse charts (what they show, highest and lowest bar) and of the map legend. Browse links with `poziom=` no longer show Streamlit's „created with a default value” warning.
- Embeddable widget: `?widget=mapa|wykres` with the browse link parameters (plus `nazwa` for a committee or candidate) renders only the map or chart; „Osadź na stronie” in the browse panel gives the `<iframe>` code for the current view.
- Precinct results: plain view `mart.v_precinct_results` (Sejm, president, EP; prompt-visible for questions about an *obwód*), `GET /precincts` (precincts of a gmina with turnout and winner, or one precinct in full) and the „Wyniki obwodowe” panel with a precinct picker; one curated example.
- Ready-made reports without the LLM: `GET /reports` and `GET /reports/{id}` run the curated SQL examples (grouped by election family) through the SQL guard and the read-only role; panel „Gotowe zestawienia” with table, chart, map and exports.
- PKW compliance report: the build stores every consistency check a family-year passed in `mart.build_checks`; `GET /checks/{election}/{year}` and the „Zgodność z PKW” button on the election card list them.
- Source files per result: `GET /sources?election=&year=` lists the KBW files an election was built from (one chamber's files in the shared Sejm/Senate directory, plus the PKW bundle page for 2019/2023); the election card and the answer's SQL panel link them.
- UI: answers with one row per year (and optionally per party) draw a line chart over time; the person card has a „Zgłoś błędne połączenie osoby” form (`POST /feedback/person`, appended to `feedback.jsonl`).
- Exports: every table also downloads as XLSX and Parquet; `GET /packages/{election}/{year}` and an election-card button give a zip with turnout and results at every level and round (plain CSV) and a README with the column dictionary.
- Mart: Sejm and Senate 1991, 1993 and 1997 (precinct level; Senate 1991 candidates only), reconciled with PKW, with the national lists as district 0, list blocs, pre-1999 geography and seat checks (Hare-Niemeyer and modified Sainte-Laguë 1991, D'Hondt 1993/1997); party families for UD/KLD (UW/PD), POC/PC, NSZZ Solidarność (AWS), WAK/Ojczyzna.
- Mart: candidate ages (`age`) in `sejm_candidates`/`senat_candidates` for 1991–1997 (checked: every candidate 21+), shown in `v_person_history`; Sejm 1997 national-list positions checked against the registered national lists (OGPOL), with named exceptions.
- Mart: president 1990 and 1995 (both rounds) and referendums 1996 and 1997 at precinct level, reconciled with PKW; pre-1999 gminas keep their old code (`teryt_gmina_pre1999`) and voivodeship, views show them at country level. President 2000: Warszawa-Centrum precincts split into today's districts through the 2001 precinct addresses.
- Mart: local elections 1998 (sejmiki, gmina and powiat councils, Rada m.st. Warszawy and the Warszawa-Centrum districts), reconciled with PKW's announcement; seat check with the 1998 thresholds; party families AWS (with AWSP), Przymierze Społeczne (PSL family), RPO, Rodzina Polska. UI maps cover 1998 codes.
- Local elections 1998: use the KBW per-precinct files (sejmik and powiat per-district workbooks, gminas up to 20,000 inhabitants, mazowieckie summary) for precinct-by-precinct checks of protocols, list and candidate votes, district totals and PKW's council totals; load sejmik ballots issued; fix the Powiat Kartuski district 4 list number and four surnames "1" (PRAWDA in the per-precinct files); named-gap checks for the sejmik totals and the small-gmina district/candidate/list counts.
- GUS context statistics per gmina, powiat and voivodeship, 1995–2024 (population, urban/rural, area, density, registered unemployment, salary) as the `gus` mart family (`gus_units`, `gus_indicators`, `v_gus_units`), fetched from the GUS Local Data Bank by `scripts/fetch_gus_bdl.py`; answers that read them show the CC BY 4.0 attribution.
- Seat check for the European Parliament 2004–2024: D'Hondt nationally among committees with 5%, then largest remainders between a committee's district lists (`mart.allocate_seats(..., 'hare_niemeyer')`).
- Weekly source workflow opens a pull request with re-staged parquet and manifest when KBW republishes files, after building the whole mart with every check (draft when a check fails).
- Person timeline: `GET /persons/{person_id}` and `GET /persons?name=` (read-only mart role, fixed SQL); the UI shows every candidacy of a person from an answer with how candidacies were linked; "Pobierz CSV" under every result table (`;`, decimal comma, UTF-8 BOM).
- Maps: results from 1990–1997 by voivodeship draw the 49 voivodeships of 1975–1998 (unions of current gminas). Gmina results with `teryt_gmina_pre1999` colour current gminas through `geo/gminy_pre1999.json` (all 2527 old codes listed; 2526 mapped, Ostrowice left out). Gminas split off later are drawn inside their parent for the years before the split.
- Maps: 2001 voivodeship maps keep Sławków in małopolskie, and maps up to 2002 keep Szerzyny in podkarpackie. Dukla includes Jaśliska before 2010.
- Browsing without the LLM: API `/elections`, `/turnout`, `/results`, `/units`, `/units/{teryt}` (fixed read-only SQL) and UI panels "Przeglądaj wyniki" (turnout or party/candidate results per unit with table, chart, map and CSV), "Karta gminy / powiatu / województwa" (turnout over time, winners, GUS) and "Co jest w bazie".
- Sejm seat simulator (2001 on): `GET /seats/simulate` and a UI panel recompute seats per committee with another method (D'Hondt, Sainte-Laguë, modified Sainte-Laguë, Hare-Niemeyer), thresholds for committees and coalitions, minority exemption or one national district; the official settings reproduce every official result 2001–2023.
- Browse: `GET /change` and a "Zmiana" view show each party's change in percentage points against the previous Sejm, sejmik or EP election per unit; a ranking switch shows the 20 highest or lowest units; the unit card compares turnout with a second unit; the seat simulator shows votes per seat and the votes for committees without a seat.
- Seat simulator: merge committees into one coalition list (`merge=` committee ids; votes summed per district, coalition threshold).

### Changed

- Thumbs-up no longer turns an answer's SQL into a few-shot example by itself: the pair is queued in the feedback log and `scripts/add_sql_example.py --review` runs it, shows the rows and adds it to the curated file only when accepted. Unreviewed `user_confirmed` examples are removed from the OpenSearch index at startup.
- Production setup: Terraform for Hetzner (`infra/hetzner`: server with in-place rescale, data volume, firewall, Storage Box, cloud-init), `deploy/docker-compose.prod.yml` with Caddy (TLS, `/api` to FastAPI), GHCR images (`images.yml`), a deploy workflow (staging after every main build, production after approval) with `deploy/update_app.sh` and `deploy/smoke_test.sh`.
- Mart deployment without downtime: CI publishes `mart.dump` (release `mart-latest`); `deploy/deploy_mart.sh` restores it into the unused mart database and switches the API (`MART_DB`); `build_mart.py --derived-only`.
- CI: lint job (ruff, mypy with a baseline, pip-audit, offline Markdown links), mart dump cache keyed by data and builders, size report; Dependabot.
- Docs: `docs/RUNBOOK.md`, `NOTICE` (data sources and licences), `docs/ROADMAP.md`; superseded design notes moved to `docs/history/`.
- Dependencies: FastAPI 0.162 (Starlette 1.10), uvicorn 0.54, pydantic 2.14, pyarrow 26 (published advisories for Starlette 0.38 and pyarrow 18).
- `build_mart.py --jobs N` builds families in parallel processes (CI uses 3); `--skip-derived` loads family-years without rebuilding persons and views.
- Entity resolution: a capitalized or named surname beats a voivodeship or powiat adjective ("Mazowieckiego", "Tadeusz Mazowiecki" are the person; "w województwie mazowieckim" the place); a matched party alias is not a place ("PiS" is not Pisz); 1975–1998 voivodeships are dropped when a current place matched and the question names no earlier year or "województwo".
- Entity resolution: a person matches only through a word that names the surname (capitalized and not a party name when no given name is given, never the given-name word), so common words such as "w gminach", "turę", "zdobyły" or "PiS" no longer suggest persons (Gmiński, Tur, Zdobylak, Piś).
- Persons: national namesakes with one given name are split by voivodeship of residence (unless occupation, place or birth year link them) and by 1990s register birth years more than 3 apart; abbreviated 1991–2009 names ("Donald TUSK") join the person with the full name when residence or birth year confirms it (≈3,080 candidacies); local candidacies whose age contradicts a national candidacy (minimum age, 1990s ages) are no longer linked; overrides for Bartoszewski (father and son), Hofman, Kośla and Hatka. 62,535 → 60,681 national persons.
- Persons: the EP 2014 candidate and local candidate from Głowaczów is no longer merged with former president Aleksander Kwaśniewski (`person_overrides.csv`).
- `v_person_history` is a materialized view with indexes on `person_id` and `full_name` (trigram): person questions take milliseconds instead of 1.4 s.
- SQL guard also rejects quoted system functions (`"pg_read_file"(...)`) and sequence functions (`nextval`, `setval`, ...).

- `Razem` and `Bezpartyjni` aliases match only the party and the Bezpartyjni Samorządowcy movement (local committees such as "ZAWSZE RAZEM" no longer count as Razem in `v_party_results`).
- Every question goes to LLM SQL over the mart first; the legacy Sejm templates run only when it returns nothing for a plain Sejm question (not a clarification answer, follow-up or mart-only election).
- The SQL prompt describes only the relations of the election kinds the question names (plus elections, persons and cross-election views); about 7–17k instead of 27k characters of schema for such questions.
- `/ask` returns numeric values as JSON numbers (`34.27`, not `"34.27"`); questions are limited to 1000 characters.

- Questions about president, referendum, sejmik, mayors, European Parliament or Senate go to LLM SQL over the mart first instead of being matched to Sejm templates.
- Candidate `full_name` is always "Given names SURNAME" (registers that publish "SURNAME Given names" are reordered).

- Dynamic SQL (`api/services/dynamic_sql.py`) now targets only `mart`: queries are validated with sqlglot and run as the read-only `plujka_mart_reader` role (`MART_DATABASE_URL`) with a statement timeout and row cap, with one repair attempt. It no longer queries `kbw_facts` or other public tables.
- `scripts/kbw_stage_duckdb.py` stages strictly (explicit delimiter, no `ignore_errors`, row-count check) and also stages XLS/XLSX; previously `okregi_sejm` lost 33 of 41 rows.
